# multi-agent-docs

一个 Claude Code 技能(skill),用于规范多个 AI 编码 agent 协作开发同一个仓库时的
文档组织方式 —— 例如 Claude Code 读取 `CLAUDE.md`、Codex 读取 `AGENTS.md`。

> English version: [README.md](README.md)

## 解决什么问题

当多个 agent 在同一个仓库中工作时,每个 agent 读取属于自己的入口文件
(`CLAUDE.md`、`AGENTS.md`、`<TOOL>.md`)。如果缺乏约束,共享的设计文档可能会把某个
agent 指向另一个 agent 的指令,或者默认整个项目只存在一种工具。本技能定义了一套边界
规则,让这类仓库保持一致、不互相串味。

## 模型

文档分为两个层级,层级决定了谁可以引用谁:

- **入口文档**(每个 agent 一个,文件名固定:`CLAUDE.md`、`AGENTS.md`、`<TOOL>.md`)
  —— 充当“路由”,是唯一可以放工具专属行为的地方。
- **共享文档**(文件名因项目而异:设计、环境搭建、README、架构等)
  —— 承载实质内容,所有 agent 读到的内容必须一致。

五条规则约束它们:

1. **单向依赖** —— 入口文档可以指向共享文档;共享文档绝不能反过来指向入口文档。
2. **共享文档保持工具中立** —— 使用角色化措辞(“编码 agent”、“代码审查”),而不是
   “Claude” / “Codex”。
3. **入口文档互为镜像** —— 除标题、自我排序顺序、以及确实属于工具特有的细节外,内容
   应完全一致。
4. **约束依据能力而非身份** —— 按环境“能做什么”来描述,而不是写死某台机器或某个工具
   的名字。
5. **同步纪律** —— 任何规则变更,都要在同一次改动中更新所有受影响的文档。

## 使用方式

技能本体位于 [`SKILL.md`](SKILL.md)。当一个项目已经有、或即将有多个 per-agent 入口
文档,或当你在编写、编辑、审查 `CLAUDE.md`、`AGENTS.md` 或共享文档时,该技能会被触发。
`SKILL.md` 中还包含一套审计流程、推荐的入口文档骨架,以及收尾前的检查清单。
